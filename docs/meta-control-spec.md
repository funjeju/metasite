## 1. 디자인 원칙

### 1.1 정체성

> **"이건 제품이 아니다. 관제실이다."**

- 사용자는 운영자 1명. 학습 곡선보다 정보 밀도가 우선.
- 예쁘게 꾸미지 않는다. **회색 톤 + 기능 우선**.
- 클릭 수 줄이기 > 화면 깔끔함. 자주 쓰는 액션은 1클릭 안에.
- 키보드 단축키 적극 사용 (`g s` = go to sites 등).

### 1.2 정보 밀도 기준

```
나쁜 예: "AI 사이트, 한국어, 발행 중"
좋은 예: "🟢 ai-kr | 한 | nextjs | Phase 2 | 어제 18:00 | 다음 21:00"
```

세로 공간이 비싸다. 각 사이트 카드 1줄에 7~10개 정보 밀도.

### 1.3 색상 시스템

```css
:root {
  --bg: #0a0a0a;              /* 배경 */
  --bg-elevated: #141414;     /* 카드/모달 */
  --border: #2a2a2a;
  --text: #e5e5e5;
  --text-dim: #888;
  --accent: #3b82f6;          /* 파랑 — 주요 CTA */
  --healthy: #10b981;         /* 초록 */
  --warning: #f59e0b;         /* 노랑 */
  --critical: #ef4444;        /* 빨강 */
  --info: #6366f1;            /* 보라 — 정보 */
}
```

다크 모드 우선. 라이트 모드는 옵션.

### 1.4 폰트

- 본문: `Inter`, `system-ui`
- 코드/숫자: `JetBrains Mono`, `monospace` (로그/ID/숫자에 사용)
- 한글: `Pretendard`

### 1.5 레이아웃 그리드

- 사이드바 240px (접으면 60px)
- 메인 max-width: 없음 (정보 밀도 우선, 1920px까지 활용)
- 카드 padding 12px (촘촘하게)
- 행 높이 32~40px

### 3.1 전체 구조 (App Shell)

```

├─────────────────────────────────────────────────────────┤
│         │                                               │

**TopBar (높이 48px):**
- 좌: 햄버거 메뉴(사이드바 토글) + 로고
- 중: ⌘K 검색 (모든 자식 사이트/글/페르소나/출처 통합 검색)
- 우: 알림 배지 + 프로필 드롭다운(로그아웃)

**Sidebar (너비 240px):**

```
┌─────────────────────┐
│ 🏠 대시보드          │
│ 🌐 사이트 (6)        │
│   ├─ ai-kr          │
│   ├─ travel-kr       │
│   ├─ travel-en       │

│ ⚙️ 설정              │

```

자식 사이트는 사이드바에 펼쳐 표시 (즐겨찾기). 사이트 클릭 → `/sites/[siteId]` 개요로 이동.

### 3.2 사이트별 서브 네비게이션

`/sites/[siteId]/*` 진입 시 메인 영역 상단에 탭 바 표시:

```
┌─────────────────────────────────────────────────────┐
│ ← 사이트 목록  │  🟢 ai-kr  Phase 2  [⏸ 일시정지] │

```

Phase 1 진행 중인 사이트는 "섹션" 대신 "권위 트리" 탭이 표시됨.

| 키 | 동작 |
|----|------|

- 우측 상단 [수동 트리거 ▶] → 즉시 1편 생성 시작

## 6. 인터랙션 패턴

### 6.1 인라인 편집

표/리스트 행을 더블클릭하면 그 자리에서 편집 가능.

예: 사이트 리스트의 'name' 열 더블클릭 → input으로 변경 → Enter 저장 / Esc 취소.

### 6.2 사이드 패널 (Right Drawer)

행 클릭 시 페이지 이동 대신 우측 패널 슬라이드 인. 화면 width 70%까지 확장 가능. ESC로 닫기.

상세 보기 → 편집 → 저장 → 패널 자동 닫힘.

### 6.3 드래그앤드롭

- 권위 트리: 의존성 화살표 끌어서 변경
- 섹션 순서: 드래그로 정렬
- 칸반 보드: 카드를 다음 단계로 끌어 강제 진행

### 6.4 일괄 작업

표에서 체크박스 다중 선택 → 하단에 액션 바 등장 ("선택 5개: [일시정지] [아카이브] [...]").

### 6.5 토스트 알림

성공/실패는 좌하단 토스트로. 자동 5초 사라짐. 실패는 [재시도] 버튼 포함.

### 6.6 확정 모달

위험한 액션(삭제/일시정지/재발행)은 항상 ConfirmDialog로 한 번 더 확인. 사이트명 타이핑 요구하는 강한 확인도 옵션.

```
┌─────────────────────────────────────────┐
│ ⚠️ 사이트 삭제                           │
│ 이 작업은 되돌릴 수 없습니다.            │
│                                         │
│ 'travel-kr'의 모든 데이터가 삭제됩니다: │
│ - 142편의 글                            │
│ - 5명의 페르소나                        │
│ - 1,247명의 뉴스레터 구독자              │
│                                         │
│ 사이트 ID를 입력하여 확인:              │

|--------|-----------|------|
| / 대시보드 | `child_sites`, `alerts` | 상태/알림 즉시 반영 |
| /sites/[id]/queue | 4단계 큐 컬렉션 모두 | 파이프라인 실시간 시각화 |
| /sites/[id]/posts | `curated_posts` | 새 발행 즉시 보임 |
| /alerts | `alerts` | 새 알림 실시간 |
| /failed-jobs | `failed_jobs` | 재시도 결과 실시간 |

다른 페이지는 폴링 또는 새로고침 시 fetch.

**비용 주의:** 같은 페이지에서 여러 사용자가 보는 게 아니라 운영자 1명이라 부담은 적음.

## 8. 모바일 미니멀 모드 (선택 사항)

운영자가 외출 중일 때 핸드폰으로 보는 용도. 핵심 4개 페이지만:

- 대시보드 (사이트별 핵심 상태)
- 알림 (확인 + 해결됨 표시)
- 검수 대기 글 (간단 승인/거부)
- 비용

화면 < 768px 에서 자동 전환. 사이드바 접힘. 텍스트만 읽도록 최적화.

## 10. 페이지별 데이터 페칭 전략

```typescript
// 패턴 1: 정적 데이터 — Server Component
// (예: /prompts 페이지의 prompt_assets)
export default async function PromptsPage() {
  const prompts = await getPrompts()
  return <PromptsList prompts={prompts} />
}

// 패턴 2: 실시간 — Client Component + onSnapshot
// (예: /sites/[id]/queue)
'use client'
export function QueueClient({ siteId }: Props) {
  const [scout, setScout] = useState([])
  useEffect(() => {
    const unsub = onSnapshot(
      query(collection(db, `sites/${siteId}/ai_scout_queue`)),
      (snap) => setScout(snap.docs.map((d) => ({ ...d.data(), id: d.id }))),
    )
    return unsub
  }, [siteId])
  return <KanbanBoard scout={scout} ... />
}

// 패턴 3: 자주 갱신되지만 실시간 불필요 — SWR
// (예: /sites/[id]/analytics)
const { data } = useSWR(`/api/sites/${siteId}/analytics`, fetcher, {
  refreshInterval: 60000,        // 1분마다 갱신
})
```
